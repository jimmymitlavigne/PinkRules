# NewsBilingual 0.7.3

Quantumult X 新闻双语与正文广告隐藏。默认 Google 翻译，可配置 DeepL、Gemini、DeepSeek。

## 安装 / 更新

在 QX「重写引用」添加或刷新：

https://raw.githubusercontent.com/jimmymitlavigne/PinkRules/master/quantumult/news-bilingual/NewsBilingual.snippet

只需导入这一个链接；必需的 JS 会通过订阅自动加载。启用重写与 MitM，安装并信任 QX 证书，使用订阅中的 hostname。避免同时启用重复版本。

更新后确认版本为 **0.7.3**，完全退出再打开新闻 App。FT 需要重新触发启动请求。更新前保存的旧文章若没有按钮，需要让 App 重新联网载入该文章；仅退出重开不一定会更新离线缓存。

## 0.7.3：依据新增抓包补充执行诊断与缓存处理

本轮目录包含 1,538 条记录，其中 1,245 条为新增记录，并非此前只有 293 条的压缩包。新增记录确认 NYT、FT 已收到 0.7.1 客户端，WSJ HTML 已包含 0.7.1 内嵌客户端；但“脚本已返回”仍不能证明手机已执行。抓包中的脚本在 Chrome 和 WebKit 本地回放均可启动，不能据此确认手机故障的唯一根因。

- 四款 App 的诊断新增“客户端执行”：区分开始执行、初始化完成、启动异常及旧客户端驻留。异常只记录入口/创建按钮/监听页面/识别正文等固定阶段，不记录正文、异常堆栈、Cookie 或 API Key；按钮识别状态独立保留。记录是最近收到的回报，需结合时间和版本判断。
- 注入客户端统一输出为 ASCII 代码，中文文字以 Unicode 转义保留，避免继承页面编码时破坏脚本语法。WebKit 无页面编码声明的人工样本曾复现原代码解析失败；修改后可启动并显示正确中文按钮。原站正文和编码声明保持原样，此项尚不能视为用户手机故障的已确认根因。
- 对确实已改写的 HTML、NYT 正文响应和 FT 启动响应统一添加缓存重新校验要求，移除旧的 ETag、Last-Modified 和 Age，减少后续继续复用旧注入内容的机会。未修改的原生响应保持原样。原有 WSJ 缓存处理沿用。
- 新数据中的 NYT 正文请求存在空体 304 响应。此类请求不含正文，无法补注入；QX 的正文重写也不会处理空响应。本版不能追溯修改 App 离线文件或替代 App 自身缓存管理，旧文章仍需实际联网重新载入完整响应。

新版 WebKit 回放通过：实际 WSJ HTML 中按钮位于视口内且可点击，点击生成模拟双语，再点击恢复原文。FT、NYT 仅有客户端脚本回放及人工正文验证，缺少对应手机页面完整 DOM。翻译使用本机模拟，未向外发送抓包正文。

经济学人的新增正文仍为原生 GraphQL 数据，网页域名记录为图片，未得到可验证的正文 WebView。默认继续保留原生阅读主题，强制网页选项仍需手动开启且不保证成功。**本版尚不能承诺四款 App 每篇原生文章都有按钮，也未完成用户 iPhone 上的故障复测。**

更新后打开文章，再查看诊断页该 App 的“客户端执行”和“按钮运行状态”：有脚本返回但没有执行记录，可能涉及执行限制、旧页面或回报被阻断；“未找到可见正文”则需继续检查该文章的页面结构。不能只凭一条记录推断原因。

## 0.7.2：隔离启动阶段的可选功能异常

针对用户反馈 0.7.1 四款 App 均无按钮，检查了发布文件一致性，并复测普通浏览器场景；普通场景未重现。发现 0.7.1 新增的主题监听处于首次正文扫描之前，接口缺失、返回异常或监听注册报错会中断初始化。本次将它移到控件初始化和首次扫描之后，并隔离注册/释放异常。诊断上报的同步异常也不能再中断正文处理。

四域名 × 六种人工场景（正常、主题接口缺失、返回 null、调用抛错、监听抛错、诊断请求同步抛错）共 24 项：旧版 18 项出现初始化中断或异常，新版全部完成初始化、点击翻译、图标切换、重复加载和释放。正常深浅模式切换测试保留。**这些模拟故障证明代码风险已修复，不证明用户手机遇到的必然是同一根因；仍需当前设备诊断记录。**

诊断页现在为四款 App 分别保留客户端返回及按钮运行状态。更新订阅并完全退出 App 后重开文章，再看当前时间、版本对应的记录；若诊断页本身无法打开或仍是旧版本，说明还没有证据确认新版重写生效。原生正文没有按钮入口的限制及经济学人强制网页选项保持不变。

## 0.7.1：经济学人阅读主题与按钮诊断

- 默认保留经济学人原生阅读器，不再将 `forceAppWebView=false` 自动改成 true。旧版为了尝试添加按钮而切换阅读器，可能导致原生深色模式或登录体验丢失；这是明确存在的行为风险，但现有抓包没有失败页面的 HTML，不能断言每篇异常的唯一原因。
- 原设置 `economistWebView` 不再继承，新设置 `economistForceWebView` 默认关闭。需要尝试时，在诊断页手动开启“强制经济学人网页阅读器”；该选项可能再次失去原生主题。已被旧版改写并缓存在 App 的文章仍需重新联网加载，更新脚本无法追溯修改离线文件。
- 译文移除固定浅色底，使用透明背景，文字颜色跟随对应原文段落；系统主题或页面主题改变时更新。只改变译文自己的样式，不覆盖原站正文、背景、图片或主题设置。
- 经济学人已有 HTML/WebView 正文内嵌客户端，并保留外链后备与 CSP nonce；不修改 CSP。减少单独 `client.js` 加载失败导致没有按钮的情况。若 App 使用原生组件渲染结构化 JSON，仍无按钮注入入口。
- 诊断页分别记录“经济学人正文入口 / WebView 注入 / 外链脚本返回 / 按钮运行状态”。原生结构化正文、HTML 已注入、客户端已找到正文是不同阶段；需结合当前文章打开后的时间判断。

提供的 293 条记录中，31 条 GraphQL 响应在默认配置下全部保持原样；其中有 20 份文章正文数据。`www.economist.com` 的 61 条记录均为图片请求，缺少文章 HTML，不能逐篇复现本次有/无按钮及深色模式问题。本地人工页面已验证主题切换、内嵌启动与独立运行记录，手机仍待复测。**本次没有实现经济学人全部原生文章的翻译按钮。**

## 0.7.0：跨页面的本地持久翻译缓存

默认开启。文章翻译成功后，将原文片段和对应译文保存到 QX 本机持久存储；刷新、退出页面再打开，点击翻译时可复用已有译文，避免再次请求翻译服务。客户端仍会调用 QX 本地接口，缓存命中的段落不发往 Google / DeepL / Gemini / DeepSeek。

- 按原文片段、翻译服务、当前模型或 DeepL 主机、翻译协议区分。原文更新只翻译变化部分；相同片段可跨文章复用。一般 UI 版本更新不会清空持久缓存，修改翻译语言或指令时会更新缓存协议。
- 成功结果最多保存 30 天；使用 128 个固定存储桶，每桶最多 8 段、8,192 个字符，最多 1,024 段。较长内容会更早触发容量淘汰；超大译文可以正常返回但不缓存。失败、超时和格式不完整的结果不写入。
- 诊断设置页增加“本地持久翻译缓存”开关和“清除翻译缓存”按钮。最近翻译记录显示“缓存命中 / 提交服务”的段落数，不显示缓存正文。关闭开关后不读写持久缓存；如需删除已有数据，请点击清除。
- 缓存仅在本机保存原文片段、译文、服务/模型标识和时间，不保存文章 URL、Cookie 或 API Key，也不会上传到 GitHub。清除时使旧请求失效，清除前发出的请求不能再把结果写回缓存。已打开页面的内存译文需重新载入页面后清除。

缓存不是离线文章库，也不能为未注入客户端的旧文章补按钮。首次同时打开同一未缓存内容时，独立 QX 脚本仍可能同时请求；本功能不承诺跨进程请求严格只执行一次。缓存存储不可用时仍返回正常翻译，下一次可能再次请求。

## 0.6.4：缓存页面恢复、单图标玻璃按钮与广告空白

- WSJ 等已运行新版客户端的页面，返回之前载入的文章、恢复页面或重新插入文章节点时重新识别正文；按钮被页面移除后自动补回。同版客户端重复执行只刷新检测，支持清理的新版客户端升级时释放旧观察器和定时器，避免重复按钮。
- WSJ 新改写的 HTML 增加联网重新校验缓存的响应头，并去掉旧的 ETag / Last-Modified。**QX 无法修改 App 完全不发请求的旧离线缓存，也不能保证 App 自己的下载管理遵守 HTTP 缓存头。** 更新前未注入脚本的旧文章仍需实际联网重载一次；此项不能追溯修复已有离线文件。
- 右下角改为 52 × 52 的半透明圆形玻璃按钮，仅显示一个图标。翻译图标点击后显示双语并切换为文档图标，再次点击恢复原文。保留无障碍文字、明暗模式和减少透明度选项；采用网页样式模拟 Liquid Glass。
- 四款受支持的网页/WebView 正文共用广告布局处理：已确认的广告外层即使内部广告被 SDK 移除也继续收起；页面重新写入广告显示样式时再次收起。外层改为新闻文字或媒体时恢复，避免误删正文。广告块在布局中不占高度和内外边距，保留 DOM 以兼容页面框架。

本版通过四域名人工广告布局、WSJ 缓存 DOM 返回/客户端替换及已有 57 段 WSJ 正文离线回放。翻译使用模拟服务，仍需 iPhone 验证；**原生 iOS 广告控件的占位无法由网页脚本移除，不能承诺四款 App 所有原生页面都没有广告空白。**

## 0.6.3：WSJ 内嵌客户端启动

针对“WebView HTML 已注入，但没有 WSJ 外链客户端返回或运行记录”的反馈，WSJ WebView 现在直接在已改写的 HTML 中嵌入客户端，避免启动仅依赖第二次 `client.js` 请求。同时保留绝对地址的外链脚本作为后备：页面禁止内联脚本但允许外链时仍可启动；两路都执行也只创建一个控件。

内嵌内容仅含客户端代码和公开配置（服务名称、是否配置 Key 等），不含 API Key。原正文、权限和原站脚本保留，不修改 CSP；已有 nonce 沿用。原有液态玻璃样式及广告整块收起保留。

诊断新增独立的“WSJ WebView 注入”和“WSJ 外链脚本返回”，不再需要用 FT 等应用的最近脚本记录推测 WSJ 状态。**内嵌启动成功时可以没有外链返回记录，应看“WSJ 按钮运行状态”。** 本次改动针对已观察到的加载断点；不能仅凭日志判定外链没有记录的确切原因，也不能声称手机故障已经复测修复。

## 0.6.2：WSJ WebView 按钮显示与诊断

- 按钮挂载到文档根节点，避免受 `body` 的变换、裁剪或替换影响；保留液态玻璃样式及右下角位置。
- 在 `webview.wsj.com/webview/` 路径中，以已有抓包的 `p[data-type="paragraph"]` 标记补充正文识别，即使外层不是标准 article 容器也可尝试识别。至少两个可见段落且合计 100 字符；不会套用到首页。
- 页面恢复、加载完成、窗口大小和可见状态变化时重新检测；按钮样式沿用加载器 nonce，以兼容使用同一 nonce 的 CSP。
- 新增“WSJ 按钮运行状态”：脚本已运行但未找到可见正文、正文已识别但按钮不可见、按钮已创建且位于视口内。仅记录枚举状态、段落数量、域名、时间和版本；不记录正文、文章路径或 Cookie。

人工 WebView 场景测试及已有 57 段 WSJ 正文离线回放通过。**这不证明用户手机上本次失效的根因已确认，也不增加 WSJ 原生正文的按钮支持。** 更新后退出 WSJ，重开未缓存文章；仍无按钮时查看诊断页“WSJ 正文入口”和“WSJ 按钮运行状态”的最新时间与版本。只有旧记录或没有回报时，不能据此推断当前文章已成功运行。

## 0.6.1：收起广告外层空白

页面去广告会继续向外检查广告专用容器，把固定高度、内边距、外边距和 Advertisement 标签一并收起，使前后正文衔接。只有内容全部属于已识别广告的容器才处理；同层有新闻文字、图片、图表、视频或交互控件时保留。动态插入的广告同样处理，容器改为展示新闻内容时会恢复。此修复保留 DOM 节点以兼容页面框架，视觉和布局上整块隐藏。

**收起外层占位需要网页/WebView 客户端已运行。** 清空广告响应本身无法控制原生 App 的布局；不能据此承诺 WSJ 原生页面没有空白。已有 WSJ WebView 抓包在本版离线回放 57 段翻译与按钮切换通过，但不证明手机目前打开的正文属于该入口。

## 0.6.0：经济学人实验性适配

历史版本根据抓包加入 `ArticleQuery` 单篇正文、`ArticlesQuery` 批量正文、首页和专题列表适配。仅将已识别文章的 `contentIdentity.forceAppWebView` 从 false 改为 true，尝试让 App 使用自身的网页正文入口，再由 HTML 重写加载翻译按钮。**0.7.1 起默认关闭且不继承旧开关，详见上方说明。**

**这个字段已在真实响应中验证存在，但 App 是否实际切换、是否沿用登录状态及按钮能否显示仍待 iPhone 实测。** 不将“已请求 WebView”当作按钮加载成功。若出现登录提示、页面打不开或阅读异常，请关闭该开关后重开文章；已有缓存可能需要重新联网加载。正文、图片、音频、文章 URL、权限字段与广告标签均保留。

抓包回放：293 条记录中 8 个响应、284 处标志改写通过字段保真检查；其中单篇正文 4 条。5 条 Google 投放请求没有响应头/体，无法据此验证去广告效果。新增对投放接口直接返回完整 HTML 广告的清空处理；未把广告分类标签 `ABS/BSC` 当作广告开关。

## 使用

- 支持的正文右下角只有一个圆形图标按钮：**翻译图标 ⇄ 文档图标**，采用 Liquid Glass 风格半透明背景模糊、高光、明暗模式与按压反馈。兼容减少动态效果、减少透明度和增强对比度；这是网页样式模拟，不是 iOS 原生材质 API。
- 点击翻译图标（无障碍标签“显示双语”）开始逐段翻译；再次点击文档图标（“显示原文”）隐藏译文并停止后续批次。已发出的服务请求可能继续完成，但迟到的结果不会显示。
- 已完成的译文在当前页面内存缓存，切换显示不重复请求；默认另存 QX 本地持久缓存，重开文章后可继续复用。
- **默认隐藏已识别的页面广告位并收起占位空白**，不需要先点翻译。包括 NYT 广告容器、FT 广告插槽、明确标记的广告位及仅承载广告的外层占位容器；动态加入的广告同样处理。
- **默认清理已识别的 Google 广告投放、Amazon 移动广告竞价、SafeFrame 广告框架响应**。Google 流式响应保留元数据并替换广告 HTML；原生 JSON 清空广告网络列表；Amazon 使用抓包中已有的空广告结构。直接返回完整 HTML 的 Google 广告文档也清空；未知格式保持原样。此功能在响应到达后执行，可单独关闭，也会影响其他 App 使用的相同广告接口。
- 广告隐藏仅在识别到文章页面时生效；不按“广告”等正文文字、图片说明或普通 iframe 判断广告。新闻图片、图表和视频保留。

2. 展开对应的 API 设置，填写 Key；可选择 DeepL Free/Pro、修改 Gemini/DeepSeek 模型 ID。
3. 按需切换“隐藏页面广告”“清理广告投放响应”和“经济学人 WebView 入口（实验性）”。
4. 点击“保存设置”，再点击“测试翻译”；保存后重新打开新闻文章，FT 建议完全退出 App 后重开。

Key 留空表示保留原值；勾选“清除已保存的 Key”并保存才会清除。保存后输入框清空，只显示“已配置/未配置”。现有 Key 不返回网页，不写入日志或 GitHub；设置使用 QX 本机 prefs，与 BoxJS 共用。

管理页使用独立的 `.invalid` 地址，由 QX 本地重写提供；设置提交不使用新闻网站域名。页面不加载第三方脚本，配置写入要求匹配的来源与版本。QX 未启用或新规则未生效时管理地址可能无法打开，请先更新订阅并确认 MitM 含 `news-bilingual.invalid`。手机实际加载仍需验证，已有 BoxJS 可继续使用。

本机抓包可能记录你向管理页提交的 Key；分享后续抓包时请排除 `/__news_bilingual__/v2/settings` 请求。

Google 使用非正式免 Key 接口；其他服务需要自己的 Key，不会自动切换服务。Key 仅用于对应的官方翻译 API。真实付费 API 仍待验证。

[可选 BoxJS 配置](https://raw.githubusercontent.com/jimmymitlavigne/PinkRules/master/quantumult/news-bilingual/NewsBilingual.boxjs.json)：

| 字段 | 用途 |

| provider | google / deepl / gemini / deepseek |

| cleanAdResponses | true 默认清理广告响应；false 关闭 |

## 日志与诊断

在 Safari 打开 [诊断页](https://www.ft.com/__news_bilingual__/v2/diagnostic)，查看版本、内容命中、客户端加载和翻译结果，也可测试翻译服务。

QX「网络活动 → 脚本记录」搜索 `NewsBilingual`：

- `loader injected`：HTML 已加入加载器。
- `bootstrap appended format=ft-startup`：FT 启动响应已加入加载入口。
- `client.js served`：客户端请求已到达 QX。
- `translate start / success / error`：翻译请求及结果。
- `ad response cleaned`：广告响应已清理；不代表原生广告占位已消失。
- `economist webview requested`：已修改 App 的 WebView 偏好；只有后续 `loader injected`、`client.js served` 才证明进入网页客户端链路。
- `structured article detected`：识别到结构化正文，不表示按钮已注入。

诊断仅保存域名、版本、时间、类型及结果，不保存正文、Cookie 或 Key。所选翻译服务仅在点击按钮后接收可见的待译文字。
